# release-0.3.0
Date: 2026-10-14
Files: 9 | Lines: +200/-10

## What changed
- `VERSION` 0.2.0 → 0.3.0.
- CHANGELOG: `[Unreleased]` became `[0.3.0] - 2026-10-14`, with a fresh empty
  `[Unreleased]` above it. The installer fix entry gained a caveat: an
  install from before 0.3.0 may list a preinstalled Thunar as a dots
  package, and the entry says which manifest line to delete.
- New `scripts/migrations/0.2.0-to-0.3.0.sh`: a documented no-op.
- New `tests/migration-0.3.0.sh`: the real migrate.sh takes a sandboxed
  0.2.0 manifest to 0.3.0, rows untouched, and a re-run is a no-op.
- CONTRIBUTING.md step 2, README.md Versioning and the CLAUDE.md map now say
  a migration script is required for **every** release.

## Why
The user picked "cut release 0.3.0" (with the installer fix, merged first so
the release ships it). Since 0.2.0, `[Unreleased]` had collected
`dots drivers`, laptop support, default apps, Arabic fonts and several
fixes.

## Key Technical Decisions
- **Minor bump**: everything is additive, and `dots update` brings a 0.2.0
  install fully up to date (proven on the VM before this release).
- **A no-op migration rather than none.** `migrate.sh` stops at a step with
  no script, which leaves the manifest at 0.2.0 and makes doctor warn.
  Nothing needs migrating because install-suckless.sh has refreshed
  unedited stale headers itself since 0.2.0, the drivers and laptop work
  runs in the package stage, and SYSFILE rows are only written, never read
  from older installs.
- **The release docs were wrong** (found in audit): they called the
  migration optional, which would have broken this release and the next.
- The PACKAGE thunar row from older installs cannot be fixed by a
  migration, since whether dots installed Thunar cannot be told after the
  fact. Documented for the user instead.
- Tagging (`v0.3.0`, plus the never-created `v0.1.0` and `v0.2.0`) and
  pushing are left to the user, as outward-facing actions.
