## What changed
- `VERSION` 0.3.0 → 0.4.0. CHANGELOG: `[Unreleased]` became
  `[0.4.0] - 2026-10-14`, with a fresh empty `[Unreleased]` above it.
- New `scripts/migrations/0.3.0-to-0.4.0.sh`, a documented no-op.
- `tests/migration-0.3.0.sh` was renamed to `tests/migration-current.sh` and
  made version-independent. It reads VERSION, requires exactly one
  `*-to-$VERSION.sh`, and walks a sandboxed install from that step's source
  version with the real migrate.sh. CONTRIBUTING's release step 2 names it.

## Why
The user picked "push + cut 0.4.0" (2026-10-14). `[Unreleased]` held VM
detection, dwm-picom, the Fedora Server target, the installer cleanups and
the `--help` fix: additive, so a minor bump.

## Key Technical Decisions
- **No-op migration.** dwm-picom reaches every install through the linked
  config/dwm/bin, and the autostart.sh line that runs it is the user's to
  paste (rule 6), as the installer reports. An older autostart.sh's inline
  probe keeps choosing a backend meanwhile. No manifest row format changed.
- **The version-specific migration test became generic.** The old one
  hard-coded 0.3.0 and would have failed on this very bump. The new one
  never needs editing at a release and still fails when a release ships
  without its migration script.
- Tagging `v0.4.0` is left to the user, as with v0.3.0. Pushing main was
  requested.
