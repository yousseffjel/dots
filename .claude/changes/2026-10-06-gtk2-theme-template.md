## Why
Item 4 of "what is next" (2026-10-06). lxpolkit, the polkit password
prompt, links `libgtk-x11-2.0` (mdapi f44, lxpolkit 0.5.6), so it drew
GTK2's light default. The packaged route is gone: `gnome-themes-extra` /
`adwaita-gtk2-theme` exist in f43 but mdapi returns 400 for f44 and
rawhide. The user picked the palette-template option over a fixed dark rc
or skipping it.

## Key Technical Decisions
- **A whole theme, not overrides.** xsettingsd sends `Adwaita-dark` to
  GTK2 too; with no GTK2 copy installed GTK2 falls back to its built-in
  default. Verified: in the container the screenshot is byte-identical with
  and without `gtk-theme-name = "Adwaita-dark"` ahead of our rc.
- **Never replace a user's `~/.gtkrc-2.0`, unlike `gtk.css`.** Found in the
  audit. The post-command runs on every wallpaper change, including on an
  install whose installer has not been re-run since this change, so nothing
  would have backed the file up. Deviation from the plan, recorded in
  progress.md. The cost: a user with their own gtkrc gets no GTK2 theming
  until they delete it.
- **Temp file + `mv`**, so a symlink to the cache copy is replaced rather
  than `cp`'d onto itself, and no GTK2 app reads a half-written file.
- **The installer claims engine-written files it finds.** Without this, a
  `~/.gtkrc-2.0` written by an apply before the installer re-ran would be
  backed up and then "restored" by uninstall: a generated file left
  behind for good.

## Assumptions
- Type C: an rc colour string `"#rrggbb"` in `bg[STATE] = ...` is valid
  GTK2 syntax. Confirmed by the container run (no Gtk-WARNING).
- Type B: `widget "gtk-tooltip*"` matches GTK 2.24 tooltip windows. Not
  shown in the screenshot (no tooltip was open).
