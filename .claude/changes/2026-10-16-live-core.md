# live-core — J-1: install Void from the live ISO onto a mounted /mnt
Date: 2026-10-16
Files: 19 | Lines: +1258/-21 (staged, before this log)

## What changed
- New `scripts/install-live.sh` (root, on the Void live ISO). Given an
  already-mounted target root (default `/mnt`), it bootstraps
  `base-system linux-lts grub` (+ `grub-x86_64-efi` on UEFI) with
  `xbps-install -r`, after updating the ISO's own xbps. It writes fstab
  (`xgenfstab -U`), hostname, the `KEYMAP` in rc.conf, `/etc/localtime`,
  the locale (libc-locales + locale.conf), a user in wheel, both
  passwords (root locked when none is given), `/etc/sudoers.d/10-wheel`
  (checked by visudo) and the dhcpcd service. Then grub-install (EFI entry
  `Void` + the `--removable` fallback, or `i386-pc` to the whole disk),
  `xbps-reconfigure -fa` and `grub-mkconfig`. Flags: `--target`,
  `--answers`, `--dry-run`.
- Sourced modules, one per concern: `install-live-answers.sh` (dialog
  menus + a KEY=VALUE answers parser, parsed and never sourced),
  `install-live-validate.sh` (one predicate per answer; both paths use
  them), `install-live-base.sh` (preflight, firmware/disk detection,
  bootstrap) and `install-live-config.sh` (configuration + GRUB).
- `packages/live/base.lst` + `uefi.lst`. `tests/pkglist.sh`,
  `tests/void-pkgnames.sh` and ci.yml's package-names step now glob
  `packages/live/*.lst` too.
- Tests: `tests/live-answers.sh` (14 cases) and `tests/live-dry-run.sh`
  (UEFI/BIOS/MBR, every refusal, the password read-back, and a
  real-findmnt/lsblk cross-check).
- CLAUDE.md project map, CHANGELOG [Unreleased].

## Key Technical Decisions
- **Package names in `packages/live/*.lst`** (user's choice, 2026-10-16),
  over an inline array (a rule-10 exception) or a top-level list with a
  marker line. dots doctor's depth-1 glob never sees them, so a box
  installed another way gets no warning about `linux-lts`.
- **The live ISO is detected by `root=live:` in /proc/cmdline**
  (void-mklive mklive.sh:298). Every refusal is in `live_preflight`,
  before anything is printed or run. It returns explicitly, because it is
  called from an `||` list, where set -e is off.
- **The GRUB disk is derived, never asked for**: `findmnt -nvo SOURCE` (the
  `-v` drops btrfs's `[/subvol]`), then `lsblk -nrspo NAME,TYPE` up to the
  disk, which also works through a LUKS mapping later (J-4). BIOS on GPT
  requires a bios_grub partition. UEFI requires a vfat ESP mounted at
  /boot/efi.
- **Plain passwords go to `chpasswd -c SHA512`, never to bare `chpasswd`.**
  On the BIOS VM, bare chpasswd exited 0 inside the Void target and set
  nothing, so the user was left at `!` while the install reported
  success. `live_check_password` now reads /etc/shadow back after every
  password write.
- **Writes no dots manifest rows.** It creates the operating system, which
  `dots uninstall` never removes.

## Assumptions Made
- Type B: answers-file passwords are crypt hashes only (SHA-512/256). If
  wrong, accept plain text from a 0600 file in
  `live_valid_hash`/`live_answer_set`.
- Type B: dhcpcd is enabled so the first boot has a network before
  install-void.sh moves it to NetworkManager.
- Type B: root is locked when the root password is left empty (sudo via
  wheel instead).

## Test coverage
- `tests/live-answers.sh`, `tests/live-dry-run.sh`; full suite 84 OK, exit
  0; `tests/lint.sh` ✓. /test was not run as a separate phase; the suite
  ran in /code.
- 8 mutations on scratch copies (layout check ignored, live check
  loosened, EFI packages on BIOS, GRUB to the wrong device, dry-run
  executing, required keys unchecked, root allowed as the user, root never
  locked): all caught, spot-checked for the right reason.
- **Real VM run** (`void-live-x86_64-20250202-base.iso`, kernel booted
  directly with console=ttyS0, driven over `virsh console`; detail in
  `.claude/tasks/archive/live-core/context.md`):

    6.18.57_1; logged in as ysf and `sudo id -un` gave root.
  - BIOS (GPT + bios_grub) with the dialog menus found the chpasswd bug,
    fixed here. A re-run converged, it booted to login on 6.18, and GRUB
    "Advanced options" booted 6.12.113_1 (linux-lts) to login.
- **Not verified:** bare metal; Secure Boot (OVMF's keys were not enrolled);
  an MBR disk on real BIOS (the dry-run test only); the dialog Cancel path.
