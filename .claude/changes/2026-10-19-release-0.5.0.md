## What changed
- `scripts/migrations/0.4.0-to-0.5.0.sh` (new): removes the nsxiv build
  0.4.0 vendored into `/usr/local`, only when the manifest has a
  `SUCKLESS nsxiv <prefix>/bin/nsxiv` row. Exactly the files the vendored
  Makefile's `uninstall` target removed (binary, man page, .desktop, five
  hicolor icons, the examples dir; then `share/doc/nsxiv` if empty). sudo
  only when the prefix is not writable; a failure exits 1 and keeps the rows
  so a re-run converges. Then drops the nsxiv rows (others untouched), and
  deletes the untracked `suckless/nsxiv/` leftovers unless config.h was
  edited (`file_matches_history` against the committed config.def.h), the
  dir still has tracked files, or there is no git history — each kept case
  is named.
- `tests/migration-0.5.0.sh` (new): throwaway git repo + prefix, fake sudo
  first on PATH, `env -i`, all four XDG vars sandboxed. Recorded build,
  re-run, edited config.h, tracked files, unrecorded/odd rows, read-only
  prefix with a failing sudo.
- CHANGELOG: `[0.5.0] - 2026-10-19` cut, empty `[Unreleased]` above. Two
  entries corrected for release: the nsxiv one now describes this migration
  (was "the next release's migration"); the Void one lost "the port is in
  progress, works on neither distro", false once released.
- VERSION 0.5.0. CLAUDE.md: migrations map line; rule 4's "migration
  (queued)" now names the shipped script.

## Why
User's "1 + 2 + 3": the 0.5.0 release last. Every release needs a
migration step (CONTRIBUTING "Cut a release"); this one has real work,
because the old /usr/local build precedes /usr on PATH and XDG_DATA_DIRS and
would shadow the package forever, and `dots uninstall` could no longer
remove it (its source dir is gone). No header refresh is needed:
`refresh_generated_headers` already runs before every build.
