# queue-sweep-1-5
Date: 2026-08-10
Files: 12 modified/added (+ the task folder) | Lines: +609/-158

Closes `MASTER_PLAN.md` queue items 1–5 in one pass, at the user's request.
Item 6 (running the installer on real hardware) is untouched — it needs a
Fedora box, not a code change.

The five are unrelated to each other and touch disjoint files, so they shared
one slot rather than being sequenced across five.

## What changed

**1. `scripts/install-session.sh` was at exactly 250 lines, the cap.**

`session_report_daemon()` and `session_autostart_report()` moved to a new
`scripts/install-session-report.sh` (92 lines); the parent drops to **192**,
leaving room for the seventh daemon this split existed to unblock. The seam is
the one the file's own comments already drew — generating `autostart.sh` for a
fresh machine versus reporting on one that exists, which rule 6 forbids the
installer from editing.

**The sibling is resolved from `BASH_SOURCE`, not from the caller's
`$SCRIPT_DIR`**, unlike `install-restore.sh`'s equivalent. It has to be:
`install-session.sh` is *sourced*, by `install-suckless.sh` and independently
by `tests/autostart-daemons.sh`, and the latter sets no `SCRIPT_DIR` at all.

**2. CI now invokes `tests/lint.sh` and `tests/build.sh` instead of
reimplementing them.**

The `lint` job installs the three linters and runs `tests/lint.sh --strict`;
`build-suckless` runs `tests/build.sh` inside its Fedora container. Both
scripts were previously restated inline, so neither was ever executed by
anything — the `tests` job skips them by name.

`--strict` is new and is the point of the exercise. `tests/lint.sh` *skips* a
missing linter by default, which is right locally and wrong in CI: there the
tools were installed by the preceding step, so "not installed" can only mean
that install silently failed and the job is about to go green having checked
nothing. Under `--strict` each such skip is a failure.

markdownlint is now `npm install -g`'d rather than `npx`'d, so `lint.sh`'s
`command -v markdownlint` branch takes the **pinned** version; its npx fallback
would have silently resolved to latest. shfmt goes onto `$GITHUB_PATH` rather
than being called by absolute path, because `lint.sh` finds its tools with
`command -v`.

**3. The `pipefail` SIGPIPE bug in `install-restore-theme.sh`, third and last
known site.**

`theme_is_ours` and `theme_backed_up` both piped into `grep -qxF`. grep exits
on its first match, SIGPIPEs `cut`, and under `set -o pipefail` the pipeline
returns **141 — a failure — even though the path was found**. Both are now read
loops, where nothing inspects a producer's status. `|| true` is not the fix; it
maps 141 to 0, the opposite wrong answer.

**4. `xresources.dcol`'s `xrdb -merge` post-command is bounded.**

`timeout 10`, the same `STEP_TIMEOUT` `run_bounded` uses in `reload.sh`, and
degrading to a bare `xrdb` where `timeout` is absent, as `run_bounded` does.
`apply-templates.sh` runs post-commands in sequence, so an unbounded one on a
hung X server wedges every remaining template.

**5. `$XDG_DATA_HOME` for TPM — and this one was not a one-line fix.**

`TPM_DIR` in `install-restore.sh` now derives the path the way `ZINIT_HOME`
two lines above always did. But `config/tmux/conf.d/30-plugins.conf` hardcoded
`$HOME/.local/share/tmux/plugins` in **four** places, so fixing only the
installer would have it pre-clone TPM where tmux never looks — and TPM's own
bootstrap would then fetch a second copy. That is the picom lockstep hazard in
a new place, so both sides changed together.

**`tmux.conf` is not a shell.** It expands `$VAR` and `${VAR}` but has no
`${VAR:-default}`, so an unset variable collapses the path around it. Every
path now lives inside a **single-quoted** `run-shell` body, which tmux passes
through untouched for `/bin/sh` to expand; double quotes would let tmux expand
first and put the bug straight back. The bootstrap became one `run-shell` doing
its own `-d` check rather than `if-shell` wrapping a `run-shell`, because the
nested form needs an inner quoting level and there is no safe one.

**6. Two tests, one new.** `tests/tmux-tpm-lockstep.sh` guards the coupling
step 5 created. `tests/lint.sh` gained an empty-file-list guard.

**7. Docs:** `CLAUDE.md` (the CI caveat was now false; new script and test in
the map), `TESTING.md` (`--strict`, the new test, CI now calling the scripts),
`HANDOFF.md` (two new landmines, the split precedent, 8 tests → 9).

## Why

Items 1 and 2 are structural: one file could not grow, and two test scripts
could rot without CI noticing while their inline copies drifted from them.
Items 3–5 are shipped defects — a wrong branch taken on a match, an unbounded
call that can wedge a template run, and an installer step that can silently
become dead weight.

Item 5 is the one worth remembering. The queue entry named only
`install-restore.sh`, and doing exactly what it said would have produced a
worse repo than not doing it at all: two TPM clones instead of one wrong path.
The queue is a list of symptoms, not a specification.

## Assumptions

- **Type B — item 5 changed `config/tmux/conf.d/30-plugins.conf` as well**,
  which the queue entry did not ask for. Alternative considered: close it
  WONTFIX with a written reason. Rejected because `ZINIT_HOME` two lines above
  already honours the variable, so the inconsistency was real.
  *If wrong:* revert `30-plugins.conf` and drop `tests/tmux-tpm-lockstep.sh`.
- **Type B — `tests/lint.sh` gained a `--strict` flag rather than being made
  strict.** Its skip-on-missing-tool behaviour is deliberate and useful on a
  box with only some linters. *If wrong:* flip the default, drop the flag.
- **Type C — `install-session-report.sh` derives its own directory** rather
  than using the caller's `SCRIPT_DIR`, unlike the `install-restore.sh`
  precedent. Forced by `tests/autostart-daemons.sh`, which sources the parent
  with no `SCRIPT_DIR` set.
- **Unverified — `npm install -g` on a GitHub-hosted runner.** Global installs
  normally work there without sudo, but CI cannot be run from this host. The
  failure mode is loud either way: the step fails outright, or `--strict`
  catches the tool being absent.

## Test coverage

- **Full suite green, 9/9** (was 8). dunst held PID 6788 before and after, so
  nothing in the suite killed a live daemon.
- **The pipefail fix was reproduced, not reasoned about.** 200k rows with the
  target as the first row: the old shape reported NOT-FOUND on **5 of 5** runs,
  the read loop FOUND on 5 of 5. The shipped functions were then exercised
  directly against first-row, last-row and absent targets.
- **Both branches of the bounded `xrdb`** were run behind a shimmed `xrdb` on
  a sealed PATH: wedged with `timeout` present → rc=124 at 10s; `timeout`
  absent → rc=0 with `xrdb` still invoked.
- **The tmux config was verified against a real tmux 3.7b server**, not by
  reading it: a sandboxed `$HOME` with a stubbed `git`, under a custom
  `XDG_DATA_HOME` and with it unset, confirming all three paths resolve
  identically to the installer's `TPM_DIR`, and that a second run does not
  re-clone.
- **`tests/tmux-tpm-lockstep.sh` was mutation-tested — 4 mutants, all caught**,
  each confirmed applied before being judged: installer reverted to the bare
  `$HOME`; the tmux init line reverted; a second `TPM_DIR` assignment; and one
  that keeps the correct *spelling* but points at `tpm2`, which the grep checks
  alone would have missed. That last one is why the test evaluates both sides
  rather than only comparing text.
- **`--strict` was mutation-tested** on a PATH with no linters: rc=0 with three
  skips without the flag, rc=1 with it.
- **The split was mutation-tested**: with the sibling file removed,
  `tests/autostart-daemons.sh` fails loudly (rc=1) rather than silently
  defining nothing. The test itself needed **no change** across the split,
  which is the property it was rebuilt for in the previous task.
- Two bugs were caught by the repo's own tooling during this task and are worth
  recording: a comment line beginning with the word `shellcheck` is parsed as a
  directive and fails the file; and the first draft of the new lockstep test
  counted comment lines as violations — the exact "a grep hit is a place to
  look, never a conclusion" trap `HANDOFF.md` warns about.
- **Nothing ran against a real `dnf`, a real Fedora box, a live X session, or
  GitHub Actions.** The CI changes are unproven until a run happens.
