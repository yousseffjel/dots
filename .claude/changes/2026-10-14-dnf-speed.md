# dnf-speed — faster, stall-proof package installs

## What changed
- `config/dnf/30-dots-speed.conf` (NEW): dnf5 drop-in — fastestmirror=True,
  max_parallel_downloads=10, minrate=20k, timeout=30.
- `scripts/install-pkg-dnf.sh` (NEW): `dnf_speed_conf` copies it to
  /etc/dnf/libdnf5.conf.d with a SYSFILE row; `dnf_refresh` runs one visible
  `dnf makecache`. Called first by install-pkg.sh.
- `scripts/sysfile-lib.sh` (NEW): `sysfile_install`, the SYSFILE contract
  lifted out of drivers_touchpad; touchpad is now a caller.
- `scripts/install-pkg-tiers.sh`: install_tier batches a tier into ONE
  `dnf install -y --skip-unavailable` (stderr streamed indented + kept);
  `tier_settle` asks rpm per package; a failed transaction retries per package.
- `scripts/install-pkg.sh`: removed the `C Development Tools and Libraries`
  group step.
- uninstall-sysfiles.sh wording, docs/UNINSTALL.md 5e, CLAUDE.md map,
  CHANGELOG, install-container.yml (stale comments + a step asserting
  `dnf --dump-main-config` reports minrate 20480), doctor-drivers.sh SC2153
  directive (surfaced once drivers-laptop.sh stopped referencing DOTS_DIR).

## Why
Fresh F44 Server VM install (2026-10-14): 37 min for ~70 packages at one dnf
run each, then an hour stuck on `rust` — `rust-std-static` from
fedora.ipacct.com at ~3 KiB/s, above dnf's 1000 B/s minrate floor, so the
mirror was never dropped. The group step logged "group unavailable" on every
run; `c-development` exists on F44, the real error was discarded.

## Key Technical Decisions
- Persistent drop-in over per-run --setopt (user choice): `dots update` and
  the user's own dnf benefit. /etc/dnf/dnf.conf loads after drop-ins, so the
  user's own values win.
- Batch per tier + per-package fallback (user choice). rpm, not dnf's exit
  status, decides each package's outcome.
- Group install dropped rather than fixed: build.lst is the declared
  toolchain (rule 10); the group would add gdb/valgrind/perf nobody uses.

- Reviewer WARN (rc capture under set -e in dnf_install_batch): premise did
  not hold — install_tier's `|| batch=$?` suppresses set -e in the call, so
  `$?` was already right (proved by mutation). Hardened anyway with
  `|| rc=$?`, and the test's fake conflict now exits 3 and asserts "dnf exit 3".

## Assumptions Made
- (B) minrate=20k/timeout=30: drops the observed 3 KiB/s mirror without
  failing a genuinely slow (<20 KiB/s) link too eagerly. If installs fail on a
  slow connection, lower minrate in the drop-in.
- (B) dnf5 moves to the next mirror after a minrate abort (librepo mirror
  failover; reported by users, not documented). Unverified on the VM.
- (C) `20k` parses as 20480 — verified with `dnf5 --dump-main-config` on F44.
- (C) dnf5 progress and errors go to stderr — verified on F44.
