## Why
Scope K decision 2: Qt apps opened light and unstyled beside dark GTK apps.
Everything the design rests on was probed on the dev host (Arch, qt5ct 1.9,
qt6ct 0.11, the same versions Void ships) with Qt5 and Qt6 programs compiled
for the purpose, run offscreen:
- each plugin answers QT_QPA_PLATFORMTHEME=qt5ct AND =qt6ct (the scope
  file's open question), so a single value covers both;
- qt5ct and qt6ct colour files share one format (Void's .xbps colour files
  compared), so a single template serves both;
- `color_scheme_path` expands `~` and `$VAR`. The writer still writes it
  absolute, because a session without .zshenv also lacks the variable;
- a running app reloads on a RENAME in its config directory
  (QFileSystemWatcher::directoryChanged), not on an in-place edit or a
  touch. Hence the post-command, and writes by mv;
- Qt5 rejects the Qt6 16-field font string and silently falls back
  (DejaVu 12), and Qt6 takes it.

## Assumptions
- Type B: the conf is identity (written by install + switch), not palette.
  The colours alone are the template (the xsettingsd.conf precedent).
- Type B: the fixed font is left to fontconfig `monospace` (= Cascadia Code NF
  in config/fontconfig). `standard_dialogs=default`, no Kvantum.
- Type B: a theme switch rewrites a conf dots wrote even after a qt5ct-GUI
  edit, as it does for settings.ini. DESKTOP.md says how to opt out
  (remove the THEME row).
