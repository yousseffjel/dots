# idle-cost
Date: 2026-10-28

## What changed
- `config/dwm/bin/dwm-shotkey`: `xinput test-xi2 --root` now goes through an
  awk filter (`key_events`) that passes only RawKeyPress/RawKeyRelease as
  `press|release <keycode>` lines, `fflush()`ed one at a time; `listen()`
  reads those. Retry/backoff logic untouched.
- `suckless/dwmblocks/blocks.def.h`: `dwm-updates` row removed (signal 1 now
  free); intervals temp 5→15, bluetooth 30→60, dnd 5→30. cpu (2 s) and mem
  (10 s) were raised too, then restored by user decision the same day.
  Header comment records the intervals as a CPU budget.
- `suckless/dwmblocks/scripts/dwm-updates` deleted; its UPD cases removed
  from `tests/blocks-info.sh`.
- `suckless/dwmblocks/scripts/dwm-net`: Wi-Fi shows the bars only, no
  `NN%`. The signal is still read (it picks the bars). `tests/dwm-net.sh`
  expectations follow.
- blueman-applet and nm-applet dropped from autostart (rule 6, all three
  places: template-applets, report-applets, DAEMONS), from
  `doctor-daemons.sh`'s `daemon_applies`/`daemon_skip_reason`, and the
  doctor test's nm-applet skip/warn cases re-pointed at dwm-audiowatch
  (skip without pactl; a faked pactl makes it apply and warn when down).
- `suckless/dwmblocks/scripts/dwm-temp`: `read` instead of `$(cat)` for the
  hwmon name and temp1_input (10 runs: ~30 ms → ~8 ms per run).
- udiskie dropped: autostart template + report + DAEMONS, and removed from
  `packages/desktop.lst` (nothing would start it). gvfs (extra.lst) depends
  on udisks2, so Thunar's click-to-mount keeps working; thunar-volman
  auto-mounts while Thunar runs. Measured PSS 16.4 MB.
- `~/.local/bin/dwm-updates` on the dev host deleted by hand.
- Docs: KEYBINDINGS.md status-bar table (12 blocks, renumbered, intervals,
  updates paragraphs replaced), wiki/First-Steps.md (blocks + tray),
  docs/DESKTOP.md and dwm-xdg-autostart's comment (/etc/xdg/autostart
  rationale), CLAUDE.md, CHANGELOG.md (Changed / Removed / Fixed).

## Why
User asked for an audit of background resource use ("the whole idea of that
project is to be minimal"), then for these fixes. Measured on the dev host
(Void, bare metal, 23.6 h session):
- dwm-shotkey's bash: 15:01 CPU in 8832 s (~10% of a core); 40 ticks in a
  10 s sample. After: the whole chain (bash ×3, xinput, awk) 5 ticks in 20 s.
  Mouse activity in the two samples was not controlled.
- dwmblocks children: 895 s CPU / 85030 s (~1% of a core). dwm-dnd was the
  costliest per second (~42 ms wall per run, 2–3 `dunstctl` sh scripts over
  D-Bus, every 5 s).
- Applets' PSS: blueman-applet 12.7 MB + blueman-tray 6.5 MB, nm-applet
  12.7 MB. Both duplicate a bar block's click action.

## Assumptions Made
- Type B: packages `blueman` and `network-manager-applet` stay in extra.lst:
  blueman-manager is the BT block's click, nm-connection-editor the NET
  block's fallback. Installed-but-not-running costs no CPU or RAM.
- Type B: no migration for existing installs' autostart.sh (user-owned,
  rule 6); CHANGELOG tells them to delete the blocks. The dev host's own
  autostart.sh had the two blocks removed by hand (backup
  `autostart.sh.bak-applets-20261028`), udiskie's block removed the same
  way, applets and udiskie stopped, shotkey restarted. The udiskie package
  is still installed there (removing it needs sudo).
- Type B: gawk's fflush() is relied on; gawk is in Void's base-system.
