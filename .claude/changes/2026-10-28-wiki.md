# wiki
Date: 2026-10-28

## What changed
- `wiki/`: the GitHub wiki's source, 19 pages (Home, _Sidebar, _Footer, nine
  user pages, seven contributor pages). Pages link each other as
  `(Page-Name)` and repo files as absolute
  `https://github.com/YoussefFjel/dots/blob|tree/main/...` URLs.
- `tests/wiki-links.sh`: every internal link names a page, every repo link
  names an existing path, no relative links, every page is in the sidebar.
  Checked by mutation (one broken link of each kind + a page dropped from
  the sidebar: four FAILs, rc 1).
- `scripts/wiki-publish.sh` (`--dry-run`): mirrors HEAD's `wiki/` into a
  fresh clone of `<origin>.wiki.git`, commits, pushes. Refuses a dirty
  `wiki/`. Explains GitHub's "Create the first page" step when the clone fails.
- CLAUDE.md map: `wiki/` entry.

## Why
User asked to start the project wiki. User decisions: audience users +
contributors; source in `wiki/` in this repo (not wiki-only), so pages are
reviewed and tested with the code.

## Assumptions Made
- Type B: the GitHub wiki is a mirror; edits made there are overwritten.
- Type B: the publish script is a dev tool, not a `dots` subcommand.

## Test coverage
- tests/wiki-links.sh passes (19 pages, 172 links). Full suite rc=0.
- markdownlint not run locally (no node on the host); CI's lint job is the
  first run. Pages checked for line length and fences by script.
- wiki-publish.sh not run against GitHub: no SSH key reachable from the
  session, and the wiki repo does not exist until its first page is made.
