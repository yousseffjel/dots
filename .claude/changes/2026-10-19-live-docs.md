## Why
J-5 is the last row of scope J: document the live installer for users and prove the whole thing on the {UEFI, BIOS} × {plain, LUKS} matrix.

The matrix found a real first-boot bug. ly 1.4.1's `default_input = login` puts the cursor on the user line until a login has been saved (`save = true`). A typed password went nowhere, Enter sent an empty one, and ly said "authentication error". It was seen in runs 1 and 2, confirmed on screen in run 3 (typed `dots`, no asterisks), and gone in run 4 (`****` with no key pressed first).

The fix lives in `ly-theme.sh` because it is the one script that writes ly's config, so the manifest row and `--restore` come with it. A second writer would have needed both re-implemented.

## Key Technical Decisions
- **DEVIATION — ly fix inside this slot.** I offered three options: document only (my recommendation), document + fix, or fix only. The user chose "Document + fix in this slot". Scope gained `scripts/theme/ly-theme.sh` and `tests/ly-theme.sh`; plan.md records it as step 6b.
- **The originals file grows rather than staying write-once.** The old rule saved originals only when the file was absent. An existing install would then never record `default_input = login`, and uninstall would leave `password` behind. A key already in the file keeps its first line, because `/etc/ly/config.ini` by then holds our own value.
- **`--help` is read from the header** (`sed` from `# usage:` to the comment's end), not restated, following the "enumerations are drift sites" lesson.
- **The shipped example is refused on purpose.** It is still checked to load once filled in, so it cannot rot into an example that fails.
- **THEMING.md's ly paragraph states what `install-services-ly.sh` does today** (read from the code), not what an upgrade "should" do.
