# dwm-help
Date: 2026-10-14
Files: 12 | Lines: +210/-14

## What changed
- Eight `config/dwm/bin` scripts (`dwm-apps`, `dwm-clipmenu`, `dwm-display`,
  `dwm-emoji`, `dwm-keys`, `dwm-powermenu`, `dwm-theme`, `dwm-wallpaper`)
  gain the same `-h | --help` block right after `set -euo pipefail`. Each
  prints a usage line saying what it does and its key, and exits 0 before
  anything opens dmenu.
- `dwm-colorpicker`: its argument case moved above the ImageMagick and
  xdotool checks, so `--help` works without them. `--no-notify` and
  unknown-option behaviour are unchanged.
- New `tests/dwm-help.sh`: globs every `config/dwm/bin/dwm-*` (skipping the
  sourced `dwm-lib-*`) and runs each with `--help` under `env -i`, on a
  sealed PATH of recording fakes, with `timeout 5`. It fails on a non-zero
  exit, a missing usage line, or any fake being called.
- CHANGELOG [Unreleased] → Fixed.

## Why
The user asked (2026-10-14) to make sure the scripts and packages work on
Fedora Server. That verification found no compatibility bug: every package
exists on f43 and f44; every command resolves on the f44 Server VM and
reaches a fresh install via a declared list, a dependency of one, or the
Fedora base; and every `dots` subcommand and status block ran clean. It
did find this papercut: 8 `dwm-*` scripts ignored `--help` and opened their
menu (the smoke run left a clipboard menu on the VM screen). The user picked
fixing it (option 1).

## Key Technical Decisions
- One identical block per script, not a shared sourced helper: rule 2's
  spirit of self-contained scripts, and the test enforces the behaviour.
- The test globs rather than lists, so a new `dwm-*` is held to it with no
  wiring.

## Assumptions Made
- (C) Every keybind named in a usage line was checked against
  `config/sxhkd/sxhkdrc` and `suckless/dwm/config.def.h`: Super+space,
  Super+v, Super+Shift+d, Super+;, Super+/, Super+Shift+x, Super+Shift+t,
  Super+Shift+w.
