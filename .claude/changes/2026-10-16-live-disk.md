# live-disk — J-3: pick, erase, partition and mount the disk from the live ISO
Date: 2026-10-16
Files: 21 | Lines: +~1300/-120 (incl. this log)

## What changed

- **`install-live.sh` erases and prepares a disk itself unless `--target`
  is given.** Before, it needed a root you had already partitioned and
  mounted at `/mnt`. That is still the `--target DIR` path, which now
  refuses `DISK`/`WIPE` answers.
- `scripts/install-live-disk.sh` (new): which disks may be erased
  (`live_disk_list`, `live_disk_check`), the dialog menu, and the
  typed-name confirmation. With an answers file, `DISK=` and `WIPE=` must
  name the same device. Refused: read-only disks, zram, under 12 GiB
  (`LIVE_MIN_DISK_BYTES`), the disk carrying the live medium's label (read
  from `root=live:` on the cmdline), and a disk with any mount outside the
  target, `[SWAP]` included. A target mounted from another disk is refused
  too.
- `scripts/install-live-part.sh` (new): one sfdisk script per firmware
  (GPT; `dots-esp` 1 GiB or `dots-bios` 1 MiB, `dots-boot` 1 GiB,
  `dots-root` on the rest), `--wipe always --wipe-partitions always`,
  `udevadm settle`, nodes read back by `PARTN` + `PARTLABEL`, mkfs (FAT32
  `EFI`, ext4 `boot`, ext4 `void`), mount at `/mnt`. A re-run resumes a
  target already mounted from this disk's `dots-root`.
- `scripts/install-live-swap.sh` (new): `/swapfile` sized RAM ≤ 8 GiB ≤ a
  tenth of root (fallocate, chmod 600, mkswap; kept when the size and
  signature match), its fstab line at `pri=10`, `/etc/sv/zramen/conf`
  (`ZRAM_SIZE=50`, `ZRAM_COMP_ALGORITHM=zstd`) and the service link.
- `install-live-base.sh`: `live_preflight` split; the mount, disk and
  boot-layout checks moved to `live_preflight_target` (only with
  `--target`). In disk mode it also requires sfdisk, udevadm, mkfs.ext4,
  mkfs.vfat, fallocate, mkswap, blkid and numfmt.
- `install-live-answers.sh` / `-validate.sh`: `DISK` and `WIPE` keys,
  `live_valid_disk_path`.
- `packages/live/base.lst`: `zramen`.
- Tests: `live-disk`, `live-part-nodes`, `live-part-swap` (the REAL sfdisk,
  mkfs and mkswap on sparse image files, no root) and `live-dry-run-disk`.
  Shared sandboxes are in `tests/lib/live-disk-env.sh` and
  `tests/lib/live-dry-run-env.sh`. `live-dry-run.sh` was split in two at
  the 250-line cap; `live-answers.sh` gained the DISK/WIPE cases.
- CHANGELOG [Unreleased], CLAUDE.md project map, and the scope file
  (decisions 11-13, the J-3 status line, the answered open question, the
  Safety note).

## Why

Scope J decision 1 (option C, staged): fully automatic from the live ISO.
J-1 needed a hand-partitioned `/mnt`; J-3 removes that step. The layout,
GRUB on both firmwares, separate `/boot` and zram + swapfile were already
locked (decisions 2, 5-7). The sizes and the unattended-wipe rule were
asked this session (decisions 11-13).

## Key Technical Decisions

- **zram half of RAM, zstd** (user; decision 11). Read from zramen
  1.0.1_1's package first: `run` sources `./conf`; the defaults are 25%,
  lz4, priority 32767, no cap.
- **Swapfile = RAM, ≤ 8 GiB, ≤ a tenth of root** (user; decision 12).
  Computed from the disk size (root = disk − partition 1 − 1 GiB − 2 MiB),
  so the plan screen and the file agree.
- **`DISK` + `WIPE`** (user; decision 13), and a typed name on the dialog
  path.
- **Nodes read back, never built from the name.** `vda1`, but
  `nvme0n1p1`. Only `--dry-run` guesses them (`live_part_guess`). The ISO's
  lsblk 2.40.2 has `PARTN` and `PARTLABEL` (checked in the binary).
- **wipefs was dropped.** sfdisk's two wipe options clear the old table
  and any filesystem signatures where the new partitions start.
- **The disk stage runs before bootstrap, after the plan confirmation.**
  A Cancel anywhere before it writes nothing.

## Assumptions Made

- Type B: the disk stage is the default and `--target DIR` keeps the
  pre-mounted path. A target mounted from the chosen disk is resumed or
  laid out again; one mounted from another disk is refused, naming
  `--target` (deviation from the plan's "refuse any pre-mounted /mnt";
  without it a crashed run could not converge, rule 1).
- Type B: with `--target` there is no swapfile, only zram (the user's
  layout, the user's swap).
- Type B: 12 GiB minimum disk.
- Type C: a read-only disk is not listed at all, rather than shown under
  "Not offered" (the VM's read-only repo disk).

## ISO check (method)

The squashfs of `void-live-x86_64-20250202-base.iso` was extracted with
`7z`, and its `LiveOS/ext3fs.img` read with `debugfs`. sfdisk, wipefs,
mkfs.ext4, mkfs.vfat, mkswap, swapon, fallocate, udevadm, blockdev, lsblk,
blkid and findmnt are all there; partprobe is not (not needed). The pkgdb
lists util-linux-2.40.2_1, e2fsprogs-1.47.2_1 and dosfstools-4.2_1.

## Test coverage

- `tests/run-tests.sh`: 89 OK. `tests/lint.sh --strict` passed.
- Mutation testing: 28 mutants, each run on a fresh copy of the tree
  against all live tests, all caught. Two gaps found and closed: RAM
  between a tenth and a fifth of root, and sfdisk missing from the
  preflight list (now a sealed-PATH test per disk tool).
- Test-harness bugs found and fixed: `( … ) || true` switched `set -e` off
  inside the subshell, unlike the installer's plain calls; sourcing base.sh
  reset `LIVE_FIRMWARE`; the fake umount left a stale mount table.
- **VM, UEFI** (`dots-live-j3`, answers file, blank 20 GiB disk): stopped
  with Ctrl-C during the base-system install. The re-run printed "resuming
  it, not erasing", ran no sfdisk, and finished. First boot reached ly.
  `/proc/swaps`: zram0 (zstd, 2.02 GB of 3.94 GB, pri 32767) and the
  1843 MiB `/swapfile` (pri 10).
- **VM, BIOS** (`dots-live-j3b`, dialog menus): only `/dev/vda` was
  offered; `vda` was re-asked, `/dev/vda` accepted. First boot reached ly.
  Layout `dots-bios` / `/boot` / `/`; the 1945 MiB swapfile and zram were
  both active; `sudo -n` asks for a password, so the NOPASSWD rule is gone.
- Not verified: bare metal, Secure Boot, an NVMe disk (tests only), a
  disk with more than one mountpoint per partition (only the first is
  checked).

## Incident

The background console watcher for the BIOS run was killed by Claude
Code under host memory pressure (about 13 of 15.6 GiB in use). The VM
finished regardless. Its state was read from tty1 (`ps --forest`, the
tee'd log), and the waiting "Reboot now?" dialog was answered with Esc.
