## What changed
- **`scripts/migrations/0.1.0-to-0.2.0.sh`** replaces the no-op template.
  Globbing `suckless/*/*.def.h`, each generated header (`config.h`,
  dwmblocks' `blocks.h`) is handled like this:
  - absent, or equal to its def: nothing;
  - equal (git blob id) to ANY past committed version of its def: renamed
    `*.pre-0.2.0`, never over an existing backup (exit 1 instead);
  - edited: kept, with a hint to merge (`git diff d997704 HEAD -- <def>`,
    or `diff -u` without that commit);
  - no git: kept, with a report.

  It never deletes and never writes the manifest; migrate.sh records the
  version.
- **`dots update`** (`scripts/update.sh`, a new SUBCOMMANDS row):
  - Preflight refuses a non-git copy, a detached HEAD, no upstream, or a
    dirty tracked tree, all before the fetch.
  - `--dry-run` lists the incoming commits.
  - Ahead-only: exit 0. Diverged: refused.
  - Otherwise `merge --ff-only`; already up to date: no installer; else
    `exec install-fedora.sh` with the arguments passed through.
  - All logic is in `main`, called on the last line, so a pull that
    rewrites the script is safe.
- **Tests:**
  - `tests/migrate.sh`, the first ever for migrate.sh: fresh install, one
    hop, a chain, dry-run, a failing hop, ambiguity, a dead end;
  - `tests/migration-0.2.0.sh`: a throwaway git repo;
  - `tests/dots-update.sh`: a bare origin plus clones and a stub
    installer.
- **Release cut:**
  - CHANGELOG `[Unreleased]` → `[0.2.0] - 2026-10-12`, with the
    update/migration lines and a new empty `[Unreleased]`;
  - `VERSION` 0.2.0;
  - README § Versioning and the upgrade text (`dots update`);
  - CLAUDE.md: the subcommand list now points at `dots --help`, and the
    map gains update.sh and the migration.

## Why
Option 1 of 2026-10-12 ("what is next"): the repo had never been tagged,
`[Unreleased]` held 50 entries, and the morning's VM run showed an existing
install needing a manual header delete, rebuild, paste and dnf install to
reach it. Re-running `install-fedora.sh` already covers packages, rebuild
and paste reports; the gap was the generated headers, which an old build
keeps forever. The user chose "regenerate only if unedited" and
`dots update`.

## Assumptions
- Type B: `d997704` is the 0.1.0 base for the merge hint. It is the commit
  0.1.0 was dated at (CHANGELOG, `2026-09-28-changelog-contributing.md`),
  and its VERSION reads 0.1.0. The hint degrades to `diff -u` if a clone
  lacks it.

  diffutils, which is declared in no package list, while git is in
  core.lst (audit finding).
- Type B: `dots update` with nothing new does not re-run the installer, and
  says how to re-apply anyway.
- Type C: the ahead-only branch case exits 0 ("nothing to pull") rather than
  being refused (audit finding).
