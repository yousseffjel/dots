## Why

`config/zsh/` was seeded from HyDE and never de-branded, and one of the
leftovers was actively harmful rather than merely dead.

`.zshenv` is read by *every* zsh invocation, and it looped over `conf.d/*.zsh`
sourcing each file. `.zshrc` runs the same loop behind an
`[[ -o interactive ]] || return` guard that `.zshenv` lacked. The result was
that every config file loaded **twice** in interactive shells and **once in
every non-interactive shell** — zinit clone check, `compinit`, starship init and
all. Measured on the live config, `zsh -c true` cost **674 ms** against 1.8 ms
for a bare shell: roughly 570 ms burned by every script invocation and every
subshell. The file's sibling `10-env.zsh` already documented the correct design
in its own header ("Truly-everywhere env (login, scripts) belongs in ~/.zshenv
instead"); `.zshenv` simply violated it.

Two user-visible bugs fell out of the same tangle. `terminal.zsh`'s plugin
dispatch reached its `else` branch on this machine — `plugin.zsh` returns 1 on
line 3 and no oh-my-zsh is installed — so every interactive shell printed
"No plugin system found…", twice. And `terminal.zsh:165` set
`HYDE_ZSH_PROMPT="1"`, so `conf.d/hyde/prompt.zsh` initialised starship and then
`99-prompt.zsh` initialised it again.

| Measurement | Before | After |
|---|---:|---:|
| `zsh -c true` (per script invocation) | 674 ms | 4.6 ms |
| `zsh -i -c exit` (per interactive shell) | 925 ms | 392 ms |
| Startup noise in a real PTY | 4 lines | none |

## Assumptions

- **Type B — `functions/` and `completions/` are dead and safe to delete.**
  They load only via `_load_functions`/`_load_completions`, which
  `terminal.zsh` calls solely in branches unreachable here. Verified by
  execution rather than reading: in a real interactive shell `eza alias:
  ABSENT`, `fzf fn: ABSENT`, while the `cat` alias that *does* load comes from
  `60-aliases.zsh`. The reviewer independently re-traced the branch logic.
  If incorrect: restore the two directories and add an explicit loader to
  `conf.d/`, since nothing else sources them.
- **Type B — HyDE's `ffcd`/`ffch` were dropped rather than ported.** Our
  `70-functions.zsh` already had `fcd` and `fh` covering the same ground, and
  `ffch` reimplemented Ctrl-R against fzf's private internals
  (`__fzf_defaults`, `__fzfcmd`, `__fzf_exec_awk`) while `80-tools.zsh`
  already sources `fzf --zsh`, which provides Ctrl-R natively.
- **Type B — starship stays.** The user asked to drop it if another prompt
  tool was actually in use. Inspection showed `99-prompt.zsh` is the live path
  and the binary is installed; HyDE's p10k fallback was gated behind
  `HYDE_ZSH_PROMPT=1`, which nothing sets.
- **Type C — `starship.toml` ships glyph-free.** No Nerd Font is packaged, so
  every marker is ASCII or plain text that JetBrains Mono renders.
