## What changed
- New `scripts/install-services-maint.sh`, sourced by the services stage
  (`services_maintenance`, after `services_enable_desktop`):
  - `config/system/cron.weekly/fstrim` (`exec fstrim -a`) -> 755
    `/etc/cron.weekly/fstrim`, plus `runit_enable snooze-weekly`;
  - only when `/proc/swaps` lists `/dev/zram*`:
    `config/system/sysctl.d/99-dots-zram.conf` (`vm.swappiness = 180`,
    `vm.page-cluster = 0`) -> `/etc/sysctl.d/`, then `sudo sysctl -q -p` when
    the live swappiness differs and the installed file is ours.
- `sysfile_install` takes an optional 7th argument, the mode (644 default):
  run-parts runs only executables.
- `snooze` in desktop.lst, with consequence text (no TRIM is otherwise
  silent).
- `tests/services-maint.sh` (new); `tests/services-stage.sh` sandboxes
  DOTS_ETC and DOTS_PROC_SWAPS, so the end-to-end stage run never reaches
  the real /etc or reads this machine's swap.
- docs/HARDWARE.md § SSD TRIM and zram swap, CHANGELOG, CLAUDE.md map.

## Why
User asked for changes that make the system use the hardware more. Audit
(same session as vulkan-drivers) found: no TRIM ever scheduled (Void runs no
cron; /etc/cron.daily exists but nothing runs it), and swap on zram (zramen,
7.5 GiB, 2.9 GiB in use with 14 GiB RAM) at swappiness 60. User approved
both ("yes add both of them").

## Method
- snooze's runit services: void-packages srcpkgs/snooze/template installs
  upstream's `sv/` dir; upstream v0.6 `sv/snooze-weekly/run` is
  `snooze -w 0 -s 7d -t /var/cache/snooze/weekly -- sh -c "test -d
  /etc/cron.weekly && run-parts --lsbsysinit /etc/cron.weekly; touch ..."`
  — so the file must be executable and named per LSB (no dot), and a missed
  week runs at the next boot (-s 7d with the timefile).
- Boot loading: Void's /etc/runit/core-services/08-sysctl.sh runs
  `sysctl -p` on every /etc/sysctl.d/*.conf.
- 180 / page-cluster 0: the Arch wiki zram page and Pop!_OS defaults; the
  kernel's vm docs allow swappiness above 100 for in-memory swap.

## Assumptions Made
- Type B: services stage, not `dots drivers` — disks and memory, not a
  device driver. Reaches existing installs through `dots update`.
- Type B: TRIM on every machine (VMs too): fstrim -a skips what cannot
  discard, and on a VM it returns space to a thin host image.
- Type B: snooze-daily is NOT enabled, though /etc/cron.daily (makewhatis,
  shadow) also never runs on this machine — out of scope; reported to user.
- Type B: the zram file is gated on zram being in use at install time. A
  later switch from zram to disk swap leaves the file (the user's to remove).
- A swappiness applied live is not reverted by uninstall (lasts until boot).
