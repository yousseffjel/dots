# live-dots — J-2: install dots from the live ISO before the first boot
Date: 2026-10-16
Files: 15 | Lines: +~640/-20 (incl. this log)

## What changed

- **`scripts/install-live-dots.sh`** (new, sourced by `install-live.sh`):
  - `live_dots_clone`: `git clone --local --no-hardlinks` of the live clone into
    the new user's `~/dots` (home read from the target's passwd), origin set to
    the live clone's origin, `chown -R uid:gid`. An existing clone is left
    alone; uncommitted live changes are named, not copied.
  - `live_dots_grant` / `live_dots_revoke`: `/etc/sudoers.d/99-dots-live-install`
    (`<user> ALL=(ALL:ALL) NOPASSWD: ALL`, 440, `visudo -cf`), removed from the
    live side by an EXIT trap and again explicitly; success is refused while
    the file exists.
  - `live_dots_install`: `xchroot T sh -c "su - <user> -c 'cd ~/dots &&
    ./scripts/install-void.sh' && : >/var/tmp/dots-live-install.ok"`. The
    marker, not xchroot's exit status, decides success.
  - `live_dots_release`: stops processes whose `/proc/<pid>/root` is the target
    (TERM, 2 s, KILL; never by uid), then unmounts what xchroot left
    (`etc/resolv.conf sys proc dev`).
  - `live_dots_finish`: `umount -R` the target, then `reboot` on `--reboot` or a
    dialog yes; returns right after `reboot`.
- **`scripts/install-live.sh`**: new stage after `live_configure_boot`, traps
  `EXIT`→revoke and `INT`/`TERM`→exit; flags `--skip-dots` (J-1 behaviour) and
  `--reboot`; plan line for dots; header and closing text.
- **`scripts/install-live-config.sh`**: `live_drop_empty_resolv`, run on both
  paths after the last xchroot call: removes `/etc/resolv.conf` only while it is
  an empty regular file.
- **`scripts/install-live-base.sh`**: preflight requires `git` unless
  `--skip-dots`.
- **Tests**: new `tests/live-dots.sh` (7 cases, real git + fake xchroot + fake
  `/proc`); `tests/live-dry-run.sh` gains the dots stage, `--reboot`,
  `--skip-dots`, and the resolv line.
- **Records**: CHANGELOG [Unreleased] (Added + Fixed), CLAUDE.md project map,
  scope-j status + answered J-2 / Safety questions.

## Why

Scope J, J-2: the live-ISO install should end in the finished desktop, not a
tty with "now clone and run install-void.sh yourself". install-void.sh runs
sudo with stdin closed, so inside the chroot it needs a rule that asks for no
password; that rule must never survive the install.

## Key Technical Decisions

- **Local clone of the live checkout**, not a second fetch from GitHub: no
  network, and the installed commit is exactly the one being run.
- **`su -`** for a login environment: `install-services.sh` reads `$USER` for
  the login shell and the groups; with root's `USER` those would land on root.
  The VM confirmed zsh and `wheel network kvm bluetooth` on ysf.
- **No `dbus-run-session` second pass** (planned, dropped): the plain chroot
  run set the Flathub remote and the dconf color-scheme key itself
  (`dconf_cmd` already falls back to `dbus-run-session`). Only Thunar's xfconf
  prefs skip, as on every headless install.
- **No `--only-dots`** (planned, dropped): re-running the whole installer
  converges; VM run 3 proved it over an aborted target.
- **Marker over exit status**: xchroot's status is its cleanup's when the
  cleanup fails (seen on the VM), so it cannot tell a failed install from a
  busy `/mnt/dev`.
- **Reap by `/proc/<pid>/root`, never by uid**: uid 1000 on the live ISO is
  its own `anon` user (the clone showed as `anon` from the live side), and a
  desktop flavour runs a whole session under it.

## Assumptions Made

- *Type B:* the clone path is `~/dots` (no documented convention existed).
  Still open for the user.
- *Type B:* `--reboot` reboots unasked; without it an answers-file run never
  reboots, and an interactive run asks with dialog.

## Bugs found by the VM run (all fixed here)

1. **No DNS on first boot.** Each xchroot call `touch`es the target's
   `/etc/resolv.conf` to bind the ISO's over it (xchroot source, xtools); the
   empty file stays. NetworkManager handed openresolv the nameserver
   (`resolvconf -l` showed it) and the file stayed empty; zinit's clones failed.
   Reproduced by truncating and rebooting; with the file absent at boot it is
   written. J-1's `--skip-dots` path had it too.
2. **A gpg-agent from flatpak's Flathub key import** (ostree,
   `--homedir /tmp/ostree-gpg-*`) outlived install-void.sh in the target;
   xchroot's `umount -R /mnt/dev` failed, its exit status with it, and the run
   aborted after a good install (run 2; run 1 won the race).
3. `--reboot` printed "Next: … reboot" after rebooting (runit's `reboot`
   returns at once).

## Incident

A mutation of `live_dots_release`'s filter (`== "$LIVE_TARGET"` → `!= ""`) was
run while other test cases reached the function with the **real** `/proc`. It
signalled every process of the user's, ended the Claude Code session, and the
host was rebooted afterwards. Every test call now passes `LIVE_PROC`, the
mutation set was re-run safely, and the lesson is a memory
(`kill-loop-tests-never-scan-real-proc`).
