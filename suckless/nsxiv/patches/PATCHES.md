## Why it is vendored at all

nsxiv is not a suckless.org program, but it is built the same way (a
`config.def.h` copied to `config.h`, plain `make`), and Fedora does not
package it: mdapi answers 400 for `nsxiv` on f43, f44 and rawhide
(checked 2026-10-13). Fedora does ship its parent `sxiv`, which has been
unmaintained upstream since 2020. Vendoring keeps the maintained fork without
a third-party repository.

## No xresources patch needed

dwm, st, dmenu and slock each carry an xresources patch so the theming
engine can colour them. nsxiv reads X resources **natively**: `Nsxiv.window.*`,
`Nsxiv.bar.*` and `Nsxiv.mark.foreground` (see `etc/nsxiv.1`, "CONFIGURATION").
`config/theme/templates/always/xresources.dcol` sets them, and the next nsxiv
started picks them up. A running nsxiv does not reload them, which is fine
for a viewer you open and close.

## Things to know before patching it

- `version.h` is generated by `git describe`, falling back to `VERSION` in
  `config.mk`. In this tree `git describe` runs against the **dots**
  repository. dots has no tags today, so it falls back to `34`. If dots is
  ever tagged, `nsxiv -v` will print the dots tag instead.
- A patch goes in the same way as every other program here (CLAUDE.md rule 5):
  edit the sources, then commit the `.diff` and an entry in this file together.
